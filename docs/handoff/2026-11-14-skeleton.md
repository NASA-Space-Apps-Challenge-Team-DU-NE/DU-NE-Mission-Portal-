# LUNA-NAV 뼈대 공유 (2026-11-14)

저장소: https://github.com/NASA-Space-Apps-Challenge-Team-DU-NE/Lunar-Landing-Site-Navigator
규칙·명세는 `CLAUDE.md`, 구조는 `docs/ARCHITECTURE.md`, 할 일은 `TASKS.md`를 본다.

## 1. 지금 상태

- 데이터 처리(`pipeline/`)와 웹앱(`web/`)의 코드가 모두 들어 있다. **데이터는 아직 없다.**
- 저장소의 데이터 폴더(`web/public/data`)가 비어 있으면, 화면마다 "자료 없음"이 뜬다. 가짜 값으로 채우지 않는다.
  - 하늘 화면(태양·지구 위치)은 데이터가 없어도 근사 계산으로 동작한다.
- 개발 PC에서 확인한 것
  - 웹 테스트 41개, 파이썬 테스트 24개 통과
  - 타입 검사와 팀 규칙 검사(금지 문구, core 의존 방향, 난수) 통과
  - 10개 페이지, 3D 달, 전체화면, 모바일 폭 화면이 콘솔 에러 없이 뜸 (저장소에 넣지 않은 테스트용 가짜 데이터로 확인)
- 아직 확인하지 않은 것
  - `npm install` 후의 실제 Vite 빌드
  - 실제 Drive 데이터로 파이프라인 실행
  - Moon Trek 3D 표면 텍스처 로딩
- `TASKS.md`에서 코드가 있는 작업은 `리뷰` 상태다. 담당자가 확인한 뒤 `완료`로 바꾼다.

## 2. 처음 받기 (Windows cmd)

```bat
git clone https://github.com/NASA-Space-Apps-Challenge-Team-DU-NE/Lunar-Landing-Site-Navigator.git
cd Lunar-Landing-Site-Navigator
```

## 3. 웹 테스트 (모두)

```bat
cd web
npm install
npm run check
npm run dev
```

- `npm run check`는 타입 검사, 규칙 검사, Vitest를 한 번에 돌린다.
- `npm run dev`를 실행한 뒤 브라우저에서 http://localhost:5173 을 연다.
- 빌드 확인: `npm run build` 다음에 `npm run preview`
- 스모크 테스트(처음 한 번만 브라우저 설치)
  ```bat
  npx playwright install chromium
  npm run e2e
  ```

**데이터 없이 정상인 화면**
- 상단에 "데이터 산출물 없음" 배지가 뜬다.
- 각 카드에 "자료 없음"이 뜬다.
- "좌표 직접 입력"에 위도 -89.5, 경도 0 을 넣으면 오른쪽 하늘 화면에 값이 나온다. 이때 배지는 "근사 천체력"과 "지형 미반영"이다.

## 4. 데이터 만들기 (Drive 데이터가 있는 PC)

1. Google Drive 데스크톱 앱으로 `DU_NE Data`를 동기화한다.
2. 큰 파일은 우클릭 → **오프라인으로 사용 가능**으로 바꾼다.
3. 저장소 루트에서 설정 파일을 만든다.
   ```bat
   copy .env.example .env.local
   notepad .env.local
   ```
   `LUNA_DATA_DIR=` 뒤에 내 PC의 DU_NE Data 경로를 적는다.
4. 파이프라인을 설치하고 돌린다.
   ```bat
   cd pipeline
   py -3.11 -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   pip install -e .
   pytest
   python -m luna s00
   python -m luna all --workers 4
   ```
   - `s00`은 필요한 파일, 품질 상태, 빠진 파일을 확인한다. 결과는 `build\inventory.csv`.
   - `all`은 끊겨도 다시 실행하면 이어서 계산한다.
   - 단계를 하나씩 돌려도 된다: `python -m luna s10` … `s90`
   - 착륙지 일부만 계산: `python -m luna s30 --only shackleton_rim`

| 단계 | 하는 일 |
| --- | --- |
| s00 | 파일·품질 확인 |
| s10 | Horizons 천체력 |
| s20 | DEM 조립 |
| s30 | 착륙지 지평선 마스크 |
| s40 | 남극 격자 (가장 오래 걸림) |
| s50 | 레이어 |
| s60 | 텍스처 |
| s70 | 카탈로그 |
| s80 | 검증 |
| s90 | manifest·출처 |

- 결과: `web\public\data\` (커밋 대상), 확인용 그림: `build\preview\`
- 결과를 커밋할 때는 `data/` 브랜치로 PR을 올린다.

**처음 실행할 때 고칠 가능성이 큰 곳**
- **Drive 표 열 이름:** 내용을 보지 못하고 짜서, 예상 이름 목록으로 찾게 해 두었다. 못 찾으면 프로그램이 멈추고 실제 열 이름을 보여 준다. 그 이름을 아래에 추가한다.
  - `pipeline/luna/io/tables.py` 의 `COLUMN_ALIASES`
  - `pipeline/luna/catalogs.py`
- **Drive 파일 경로·이름:** 다르면 `pipeline/luna/paths.py` 를 고친다.
- **좌표계 확인표:** `docs/coordinates.md` 를 채운다 (TASKS P01b). 아래 세 가지는 가정이라 반드시 확인한다.
  - LOLA 라벨의 픽셀↔좌표 규칙
  - PA→ME 회전 방향
  - Horizons 경도 방향

## 5. 팀이 정해야 할 것 (CLAUDE.md 1.2, TASKS 7절)

- D1 제품 이름
- D2 아르테미스 후보 목록 기준
- D3 종합 점수 가중치
- D4 물·얼음 지표
- D5 18개 과학 임무 노출 여부
- D6 프로파일 값·먼지 반경·단층 경고 거리
- D7 5 m 국지 지형 범위

**문서와 다르게 한 것** (`docs/decisions.md`에 기록)
- 표 밖 시각의 천체력은 `astronomy-engine` 라이브러리 대신 코드 안의 근사식으로 계산한다.
  - 상식 검사: 아폴로 11호 착륙 때 태양 고도가 10.70°로 나온다 (기록 약 10.8°).
- 격자 원점은 `x0_km`(왼쪽)·`y0_km`(위쪽) 모서리로 정했다.
- 린트는 의존성 없는 규칙 검사로 시작했다. ESLint는 아직 없다.
