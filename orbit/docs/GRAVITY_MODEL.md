# Mode B의 GRAIL 달 중력장

현재 Mode B의 전체 임무 평가·유한 연소는 [FINITE_BURNS.md](FINITE_BURNS.md), 최신 검증은 [FINITE_BURN_VALIDATION.md](FINITE_BURN_VALIDATION.md)를 따른다. 이 문서의 기존 충격기동 수치는 이전 검증 이력이다.

Mode B는 달 중심 점질량 기준 모델과 NASA/JPL GRAIL **GL1800F**의 차수 절단 모델을 선택할 수 있다. GL1800F는 관측으로 추정한 비구면 중력장이다. 이 기능은 지형에 색을 입히는 중력이상 지도나 저장된 성공 궤적을 재생하는 기능이 아니다. 선택한 힘 모델로 초기상태, 전이와 착륙 제어를 다시 계산한다.

NRHO는 Mode B로 계산하며 별도 LLO 시작 계산도 유지한다. 설정에 중력 모델이 없는 기존 Mode B 요청은 점질량으로 해석하며, 화면에서 선택한 GRAIL 요청을 점질량으로 자동 대체하지 않는다.

## 실행과 화면

프로젝트 루트에서 실행한다.

```powershell
npm install
npm run dev
```

`NRHO` 출발 → `Mode B` → `달 중력장`에서 `기존 점질량` 또는 `GRAIL GL1800F`를 선택한다. GRAIL의 화면 선택 차수는 20, 30, 60, 90이다. 0차는 같은 GL1800F GM의 중심항 검증 기준이며 일반 화면의 새 선택 항목으로 제공하지 않는다. 각 차수의 성능과 절단 오차를 확인한 뒤 사용해야 하며, 차수가 실제 착륙 정확도를 보증하지 않는다.

모델·차수를 변경하면 표시 중인 이전 궤적을 지우고 새 계산을 요구한다. 실행 중에는 설정을 잠그고 취소 버튼으로 Worker를 종료할 수 있다. 오래된 Worker 응답은 실행 토큰으로 무시한다. 결과에는 실제 계산에 사용한 모델과 차수를 기록한다.

```powershell
npm run build
```

배포 대상은 프로젝트 루트의 `dist/`이다(`frontend/vite.config.ts`의 `build.outDir='../dist'`). 정적 파일 경로가 배포의 base URL과 일치해야 한다. 실행 시 Python, Node.js API 서버, DB, Drive 로그인 또는 NASA API 호출이 필요하지 않다. 개발 서버와 빌드 도구는 물리 계산 백엔드가 아니다. 일반 사용자의 모든 전파·최적화·검증은 TypeScript Web Worker에서 수행된다. 정적 데이터 해시 검사에는 HTTPS 또는 localhost의 Web Crypto를 사용한다.

## 계수와 물리 규약

세부 원본 출처, 전처리와 독립 기준값은 [GRAVITY_DATA.md](GRAVITY_DATA.md)에 기록한다. 배포 데이터는 `frontend/public/data/gravity/index.json` 하나에 최대 90차까지의 전역 계수와 PA→ME 회전을 담는다. 약 198 MB 원본 TAB은 앱이나 빌드 결과에 포함하지 않는다.

| 규약 | 적용 값 |
|---|---|
| 달 중력 모델 | GL1800F, DE440 PA |
| GRAIL GM | 4902800306330.2 m³/s² |
| 중력 계수 기준 반지름 | 1,738,000 m |
| LOLA 고도 기준 반지름 | 1,737,400 m; 중력 기준 반지름과 별개 |
| 계수 정규화 | 실수 geodesy 4π fully normalized |
| Condon–Shortley 위상 | 제외, `csphase=1` |
| 저장 인덱스 | `i=n(n+1)/2+m`, C/S 별도 배열 |
| 중심항 | 전처리에서 C00=1 명시; 한 번만 합산 |
| degree 1 | 원본의 0 계수 유지 |
| 조석 규약 | 원본 degree 2/3에 permanent tide 제외; 고체 조석 추가 없음 |

양의 중력 퍼텐셜을 쓰는 규약에서 달 가속도는 다음과 같다.

```text
U(r,φ,λ) = GM/r · [1 + Σ(n=2..N) (a/r)^n
                     Σ(m=0..n) P̄nm(sinφ) [C̄nm cos(mλ) + S̄nm sin(mλ)]]
a_moon = ∇U
```

중심항과 비구면항 모두 같은 GL1800F GM을 사용한다. GRAIL 가속도에 기존 달 점질량 항을 다시 더하지 않는다. 기존 점질량 모델은 기존 DE440 GM을 유지하므로, 두 일반 모델의 차이에는 작은 GM 차이도 포함된다. 고차항만 분리하는 비교에는 GL1800F GM의 0차 모델을 사용한다.

구면조화 계수는 전역 기저다. 착륙지의 경위도 ROI로 자를 수 있는 데이터가 아니다. 웹앱 경량화는 최대 degree/order 절단으로 수행하고, LOLA 지형에는 별도로 ROI를 사용한다. 계수 기준 반지름은 지표 또는 충돌 경계를 뜻하지 않는다.

## 좌표계와 미분

상태는 달 중심 J2000 축의 위치·속도와 질량이며 SI 단위를 사용한다. 내부 시각은 정적 천체력 epoch부터 경과한 ET/TDB 초다. UTC는 기존 SPICE 기반 정적 시간표로 변환한다.

GL1800F 계수는 `MOON_PA_DE440`, 지형은 `MOON_ME_DE440_ME421`이다. 전처리 시 원본 SPICE로 구한 고정 `R_PA→ME`와 기존 천체력의 `R_ME→J2000(t)`를 결합한다.

```text
R_PA→J2000(t) = R_ME→J2000(t) · R_PA→ME
r_PA = R_PA→J2000(t)ᵀ · r_J2000
a_J2000 = R_PA→J2000(t) · a_PA
H_J2000 = R_PA→J2000(t) · H_PA · R_PA→J2000(t)ᵀ
```

각 적분 내부 단계의 실제 시각에서 회전을 평가한다. 가속도 벡터 회전에 Rdot를 더하지 않으며 J2000 축 적분에 원심력·코리올리항을 중복 추가하지 않는다. 표면 상대 속도와 지형 목표의 상태변환에는 기존 올바른 Rdot를 유지한다.

`SphericalHarmonicGravity`는 Cartesian solid-harmonic recurrence로 퍼텐셜, 가속도와 Hessian을 계산한다. 정확한 극점에서도 위도 방향의 `1/cosφ` 나눗셈이나 임의 epsilon 이동이 필요하지 않다. `GrailGravityModel`은 이 값을 관성축으로 회전하며, STM 전파는 같은 퍼텐셜의 위치 미분을 사용한다. 독립 Python 기준값 및 유한차분 검사는 별도 검증 자료를 따른다.

## 전 구간에 같은 힘 적용

달 중심 가속 좌표계에서 지구·태양의 간접항을 유지한다. `Rj(t)`는 달에서 천체 j로 향하는 기하학적 위치다.

```text
dr/dt = v
dv/dt = a_moon(t,r)
        + Σ(j=Earth,Sun) GMj [(Rj-r)/|Rj-r|³ - Rj/|Rj|³]
        + a_command
T = m · |a_command|
dm/dt = -T / (Isp · g0)
```

선택한 중력 모델은 다음 구간에서 공통으로 사용된다.

1. NASA 참조 궤적에서 직접 조회한 출발 상태의 계산 coast 미리보기와 출발 전 3시간 역전파. 출발 상태 자체는 선택한 중력 모델로 장기간 전파해 만들지 않는다.
2. NRHO→LLO 전이 및 전이 shooting의 STM.
3. 실제 LLO 진입 상태에서의 대기와 DOI coast.
4. 동력 하강 제어의 shooting, 실제 경로 재전파, 적분 정밀화 검사.

Lambert, vis-viva 및 순간 원궤도 조건은 초기 추정에 사용한다. 최종 전이와 하강은 선택한 힘 모델로 다시 적분하고 검사한다. 100 km LLO 진입 조건은 순간적인 osculating 조건이며 이후 정확한 원궤도를 보장하지 않는다.

이탈·삽입·DOI는 추진제 비용을 포함하는 순간 충격기동이다. 동력 하강은 구간별 관성 가속도 명령이며 질량에 따라 실제 요구 추력이 바뀐다. 이번 중력장 확장은 유한 연소, 엔진 동특성, 자세 또는 짐벌 제한을 구현한 것이 아니다.

구간 경계에서는 실제 위치·속도·질량을 전달한다. 목표 상태로 위치를 재설정하지 않는다. 재적분과 지형·접지 검증을 통과하지 못한 전체 임무는 성공 trajectory로 반환하지 않는다. 참조 NRHO 초기상태의 출처와 현재 선택 모델은 구별하며, 원본 NASA 후속 궤적 표본으로 자체 전파를 덮어쓰지 않는다.

## 비교 결과를 읽는 방법

### 동일 PDI 상태와 동일 제어 명령

검증된 GRAIL 임무의 실제 PDI 상태에서 출발해, 같은 관성 가속도 명령과 Isp를 **GL1800F GM의 0차 중력 + 동일 지구·태양 중력**으로 재전파한다. 비교 종료 시각은 원래 GRAIL 경로의 종료 시각이다.

이 결과는 PDI부터 동일 시각까지의 종단 위치·속도 차이다. 전체 NRHO 임무의 차이, 다른 모델의 실제 접지 시각, 지형 회피 또는 재최적화된 착륙 성공을 뜻하지 않는다. 비교 경로는 3D 궤적으로 내보내지 않고 수치 차이만 표시한다. 비교 전파에서는 지표 접촉을 새로 찾거나 지형을 인증하지 않는다.

`gravity_same_controls_status`가 `computed`이고 필요한 수치가 유한할 때만 차이를 표시한다. `not_run_budget` 또는 `not_completed`이면 수행하지 못한 이유를 표시하며 값을 추정하지 않는다. 이 진단의 성공 여부는 본래 GRAIL 임무의 접지 검증과 별개다.

### 각 모델에서 별도로 최적화한 결과

화면은 이 세션에서 검증 완료된 결과의 요약을 저장한다. 중력 모델·차수 외의 입력이 모두 같은 경우에만 나란히 비교한다. 착륙 UTC, 좌표, 착륙선, 제약, 탐색 범위, 목적함수, 반복 및 시간 예산이 달라지면 같은 비교로 취급하지 않는다.

총 ΔV, 추진제, 위치 잔차, 접지 속도와 전체 실행시간을 표시한다. 실제 계산의 메타데이터가 선택한 모델·차수와 일치하지 않거나 `VALIDATED`가 아니면 비교 기록에 추가하지 않는다. 과거 요약표는 현재 실행의 성공 경로로 사용하지 않는다.

전체 실행시간은 브라우저 `performance.now()`로 측정하며 파일 로딩, 최적화와 검증을 포함한다. 브라우저·CPU·탭 부하·캐시와 탐색 경로의 영향을 받는다. GRAIL의 `gravity_cpu_ms`는 중력 평가 함수 내부에서 잰 경과시간 누적이며 운영체제가 측정한 CPU 사용시간과 다르다. 수치 잔차가 더 작다고 실제 달에서 더 정확한 착륙이라는 뜻은 아니다.

## 실패와 검증

정적 중력 파일의 고정 SHA-256, 모델·단위·정규화·위상·프레임 및 회전 행렬을 검사한다. 오류 시 다른 모델로 자동 전환하지 않는다. 화면은 중력 데이터 오류, 수치 계산 오류, 설정 오류, 충돌, 연료·추력 부족, 날짜 범위 초과, 계산 한도와 미수렴을 구별해 원문 및 조정 방법을 제공한다.

시간 또는 후보 탐색 한도에서 해를 못 찾은 것은 모든 가능한 궤도가 물리적으로 불가능하다는 증명이 아니다. 낮은 차수 선택은 계산량을 줄이는 대신 세부 중력장을 생략하는 절충이다. 시간 한도를 늘리는 것이 내부 적분 횟수 한도를 자동으로 늘리지는 않는다.

일반 검증 명령:

```powershell
npm test
npm run build
```

데이터 전처리와 독립 기준값 생성은 [GRAVITY_DATA.md](GRAVITY_DATA.md)의 개발용 명령을 따른다. 단위·합성 계수·극점·독립 벡터/Jacobian 비교, 적분 정밀화와 차수 수렴, 실제 임무 및 브라우저 검증은 각각 검사 범위가 다르다. [GRAVITY_VALIDATION.md](GRAVITY_VALIDATION.md)와 해당 원시 보고서의 입력·허용오차·결과를 함께 확인해야 한다. 이 문서만으로 특정 차수의 성능이나 실제 착륙 정밀도를 인증하지 않는다.

## 남은 한계

- GL1800F를 최대 90차로 절단하므로 원본의 고차 구조를 모두 표현하지 않는다. N90과의 차이도 N90 자체의 모델 오차를 알려주지 않는다.
- 정적 계수만 적용하며 시간가변 고체 조석과 원본에서 제외한 degree 2/3 permanent tide를 추가하지 않는다.
- 근지표의 외부 구면조화 전개와 하향 연장에는 모델 적용 한계가 있다. 계수 반지름보다 낮다고 자동으로 다른 힘 모델로 교체하지 않는다.
- NASA 참조 궤적과 실제 Gateway 운용 궤적은 다르다. 원본 궤적의 유지 기동과 다른 힘을 모두 재현하지 않는다.
- Mode B 유한 연소는 [제한된 최대 추력 모델](FINITE_BURNS.md)로 적용한다. 엔진·자세·짐벌 동특성, 태양 복사압, 다른 행성 섭동, 궤도 유지, 항법·엔진 오차 및 Monte Carlo 분산은 이 확장의 범위 밖이다.
- 지형 검증은 제공된 남극 LOLA 240 m DEM 및 표본 간격에 제한된다. 격자 사이 장애물과 토양·발판 안정성은 검증하지 않는다.
- 작은 결정론적 잔차는 구현한 모델 내부의 수치 일치도다. 실제 착륙 정확도와 임무 안전 보증이 아니다.

일반 사용자의 실행과 정적 배포 조건은 유지한다. 데이터·좌표계 및 임무 모델 문서는 [EPHEMERIS_MODEL.md](EPHEMERIS_MODEL.md), [EPHEMERIS_DATA.md](EPHEMERIS_DATA.md), [GRAVITY_DATA.md](GRAVITY_DATA.md)를 함께 읽는다.
