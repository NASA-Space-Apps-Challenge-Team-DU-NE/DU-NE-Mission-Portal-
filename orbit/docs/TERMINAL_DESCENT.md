# Mode B 종말 하강·접촉 제약

**현재 기본 입력은 이 제한을 그대로 통과한 [새 기본 예제](SUCCESSFUL_DEFAULT.md)로 교체했다. 아래 거부 수치는 이전 제어 방식의 이력이다.**

2026-11-15, Asia/Seoul. TypeScript Web Worker에 적용하며 기존 LLO/Mode A는 유지한다. 실행 중 계산 API나 Python 서버를 추가하지 않았다.

## 시연용 설계 기준

`demo-terminal-v1`은 실제 기체 측정값이나 NASA 인증 기준이 아니다. 질량중심 아래 국소 방사 방향 2 m에 접촉 기준점을 두고, 그 점과 240 m LOLA DEM 사이 여유로 구간을 나눈다.

| 접촉 여유 | 수평속도 상한 | 하강속도 상한 | 국소 수직 대비 추력 기울기 상한 |
|---|---:|---:|---:|
| 1,000 m 이하 | 50 m/s | 30 m/s | 45° |
| 100 m 이하 | 5 m/s | 5 m/s | 15° |
| 10 m 이하 | 0.5 m/s | 1 m/s | 5° |

낮은 구간에서는 더 엄격한 조건을 함께 적용한다. 사용자 접지 속도 제한이 더 엄격하면 그 조건도 유지한다. 저고도 재상승을 허용하지 않는다. 종말 구간은 최소 10초, 검사 간격은 최대 0.25초다. 추력 방향이 없거나 엔진이 꺼진 저고도 표본은 이 동력 하강 기준을 통과하지 못한다.

최종 접촉 여유는 ±0.02 m 이내이고 하강 중이어야 한다. 최종 시각보다 0.05초 넘게 앞서 접촉 허용구간에 들어오거나, 기준점이 허용오차 이상 지형을 관통하면 거부한다. 이 유한 간격 검사는 실제 다리 접촉의 연속 사건 검출·충격·지반 모델이 아니다.

## 계산 및 판정 변경

- 질량중심의 종단 표적을 지표 위 2 m로 바꾸고 운동방정식으로 재계산한다. 결과 좌표를 사후 이동하지 않는다.
- 지표 목표 위치 오차는 접촉 기준점으로 계산한다. `altitude_m`은 질량중심의 DEM 고도, `contact_clearance_m`은 접촉 여유다.
- 기울기는 중력을 포함한 총가속도가 아니라 명령 추력 벡터와 바깥쪽 국소 수직 사이 각도다. 기체 자세와 동일하다고 단정하지 않는다. 속도는 달 고정 좌표계의 표면 상대 속도다.
- 표시용으로 줄이기 전 전체 고밀도 적분 표본을 검사한다. 같은 시각의 제어 경계 전후 추력도 모두 검사한다.
- `terminal_descent`, `low_altitude_speed`, `thrust_tilt`, `contact`와 기존 위치·속도·질량·추력·지형·연속성·정밀 재적분 검사를 모두 통과해야 한다.
- 실패 후보는 전체 임무 순위에서 제외한다. 통과 후보가 없고 종말 제약 위반이 확인되면 `LANDING CONSTRAINT VIOLATION`, 빈 궤적 및 원인별 경고를 반환한다. 성공 `TOUCHDOWN` 이벤트도 만들지 않는다.
- 진단에는 대표 거부 후보의 위반 높이·값·제한을 표시한다. 모든 후보의 상세는 `joint_search.candidates`에 보존한다. 시간 부족과 미수렴은 물리적 불가능의 증명이 아니다.
- 입력 화면에 적용 제한을 표시하고 결과 `reference.terminal_descent`에 버전을 기록한다. 제한을 자동으로 완화하거나 끄지 않는다.
- 수락 조건은 유지한다. 새 기본 예제에는 조기 감속 초기 추정과 96개 적분 제어를 사용한다. 일반적인 연속 제어 전역 최적화는 아니며, 다른 입력에서는 모든 후보가 거부될 수 있다.

## 검증 결과

최종 자동 검사 **80/80 통과**, 실패·건너뜀 0개, 125.52초. 기존 Mode A·LLO 회귀, 중력·유한 연소·전체 임무·오류 진단과 새 종말 하강 검사를 포함한다. TypeScript 검사와 Vite 정적 빌드도 통과했다(13.39초). [실행 요약·소스 해시](terminal-validation.json). 전체 임무 회귀에는 기본 60초 예산을 사용하며, 시간 제한 기반 탐색의 환경 의존성은 유지된다.

- 실제 점질량 ODE로 101 m 접촉 여유부터 적분한 수직 하강 시험은 통과했다. 이것은 검사기의 양성 대조이며 전체 NRHO 임무 성공 사례가 아니다.
- 중간 속도 초과, 제어 경계의 위험 기울기, 세 고도 경계, 조기 접촉 후 복귀, 지면 관통, 재상승, 데이터 누락·NaN, 성긴 표본, 영추력, 더 엄격한 사용자 제한을 검사했다.
- 예전에 성공한 GRAIL 제어를 독립 SciPy DOP853·각도 기반 GRAIL·직접 SPICE·원본 LOLA로 재생했다. 2,112개 표본에서 속도·기울기·접촉 위반으로 거부했다. 최종 기울기는 70.8045°, 새 접촉 기준점은 지형 아래 약 2 m다. 초기상태는 저장된 PDI 상태이며 전체 NRHO 체인을 독립 재검증한 것은 아니다. [독립 기록](terminal-independent-regression.json)

### 새 GRAIL 30차 전체 임무

[원시 기록](finite-mission-30-default-terminal-constraints.json): Connecting Ridge, 2026-11-16 00:00 UTC, LLO 1,500 kg, 60초 예산. 실행 55.27초, 유한 연소 전체 임무 시도 2개, 통과 0개, 탐색 미완료다.

결과는 **LANDING CONSTRAINT VIOLATION**, 반환 궤적 **0개**다. 대표 후보는 질량중심의 최종 DEM 고도 2.000000267 m로 접촉 높이·최종 속도·수치 연속성을 맞췄다. 그러나 접촉 여유 8.91 m에서 수평속도 약 26.96 m/s, 추력 기울기 약 70.80°를 요구해 거부됐다. 마지막 점 검사만으로 통과했을 위험 경로를 차단했다.

기존 [유한 연소 보고서](FINITE_BURN_VALIDATION.md)의 `VALIDATED`는 이 제약을 넣기 전의 역사적 수치 검사 결과다. 현재 착륙 수락 결과로 사용하면 안 된다.

## 재현

```powershell
npm test
npm run build
node --max-old-space-size=256 --max-semi-space-size=8 --no-concurrent-recompilation scripts/run-finite-validation.mjs --degree=30 --budget=60 --tag=terminal-constraints --expect=guard-rejection
python scripts/verify-terminal-regression.py
```

Python 재검증에만 NumPy·SciPy·SpiceyPy와 원본 SPICE/LOLA 자료가 필요하다. 웹은 `npm install`, `npm run dev`, 정적 배포는 `dist`로 유지된다. 원본 자료 경로는 `data/config.json`에 있다. 전체 임무 독립 검증기도 새 접촉 높이와 새 정책의 독립 종말 하강 검사를 지원한다.

실제 기체 형상·다리·경사·바위, 자세·짐벌 응답, 점화 과도응답, 폐루프 유도와 불확실성은 미구현이다. 최대 0.25초 표본과 240 m 지형 사이 모든 충돌을 수학적으로 보장하지 않는다. 이 작업은 모델 안의 위험 경로 선별이며 실제 착륙 안전 인증이 아니다.
