# Mode B: 날짜 기반 NRHO → LLO → 착륙

현재 Mode B의 전체 임무 평가·유한 연소는 [FINITE_BURNS.md](FINITE_BURNS.md), 최신 검증은 [FINITE_BURN_VALIDATION.md](FINITE_BURN_VALIDATION.md)를 따른다. 이 문서의 기존 충격기동 수치는 이전 검증 이력이다.

Mode B는 출발 시각에 직접 조회한 NASA NRHO 참조 상태와 가공된 DE440 천체력·달 자세를 사용해 전체 임무를 브라우저 Web Worker에서 계산합니다. 달 중력은 기존 점질량 또는 GRAIL GL1800F 차수 절단 모델을 선택합니다. NRHO 계산은 Mode B로 고정하며 별도 LLO 시작 모델도 제공합니다. 실행 중 Python, 계산 API, 데이터베이스 또는 외부 NASA API가 필요하지 않습니다.

## 출처와 적용 범위

정적 `frontend/public/data/ephemeris/index.json`은 약 13.16 MB입니다. 지구·태양의 달 중심 기하학적 상태, MOON_ME→J2000 회전과 미분, UTC↔ET/TDB 표, 중력상수, 원본 보간 구간을 보존한 NASA NRHO 위치·속도 표를 담습니다. Worker는 검토된 파일의 SHA-256을 확인하고 누락·손상 자료를 거부합니다. 출처·전처리·보간 검사는 [EPHEMERIS_DATA.md](EPHEMERIS_DATA.md)에 기록합니다.

GRAIL을 선택하면 추가로 약 164 kB의 `frontend/public/data/gravity/index.json`을 검증해 읽습니다. GL1800F의 최대 90차 전역 계수와 PA→ME 정렬만 포함하며 대용량 원본은 런타임에 읽지 않습니다. 계수의 GM·반지름·정규화·조석 규약은 [GRAVITY_DATA.md](GRAVITY_DATA.md), 계산과 차수 선택은 [GRAVITY_MODEL.md](GRAVITY_MODEL.md)를 따릅니다. `gravity_model`이 없는 기존 설정은 점질량이며, GRAIL 파일 오류 시 점질량으로 대체하지 않습니다.

출발 상태는 NASA/JSC 공개 참조 SPK `receding_horiz_3189_1burnApo_DiffCorr_15yr.bsp`에서 추출한 type-9 구간을 해당 출발 시각에 직접 보간해 얻습니다. 원본의 7차 Lagrange 규칙·절점·구간 우선순위를 유지하고 공백을 잇지 않습니다. Earth 중심 J2000 상태에 DE440의 Moon 중심 Earth 상태를 더해 원점을 변환합니다. 원본은 다른 중력 모델과 궤도 유지 기동을 사용하므로 출발 상태의 설계 참조로만 사용합니다. 이후 상태는 선택한 모델로 적분하며 원본 SPK의 후속 상태로 바꾸지 않습니다. 실제 Gateway 운용 궤적을 뜻하지 않습니다.

| 조건 | 현재 지원 범위 |
|---|---|
| 착륙 UTC | 2026-11-01 00:00–2027-01-31 23:59:59.999 UTC |
| 천체력·달 자세·NRHO 자료 | 2026-10-16 00:00–2027-02-01 00:00 UTC; 출발 여유 기간 포함 |
| 착륙 목표 지형 | 제공된 남위 75°–90° LOLA 240 m DEM |
| LLO 진입 | LOLA 기준 반지름 1,737.4 km 위 100 km의 순간 원궤도 상태 |

출발 전 3시간 coast, 전이, LLO 대기, DOI 및 하강을 모두 데이터 범위 안에서 계산해야 합니다. 착륙 선택에는 `landing_coverage_utc`, 환경에는 `coverage_s`, 출발 조회에는 `nrho_reference`의 구간 경계·공백을 적용합니다. UTC와 TDB는 정적 변환표를 거치며 바깥으로 외삽하지 않습니다. 지원 기간의 모든 날짜·착륙지가 수렴한다는 보장은 없습니다.

## 운동방정식

상태는 달 중심 J2000 축의 `r`, `v`, 질량 `m`이며 SI 단위를 사용합니다. 달 중심은 가속하므로 지구·태양의 간접항을 포함합니다. `R_j(t)`는 달에서 천체 j로 향하는 기하학적 위치입니다.

```text
dr/dt = v
dv/dt = a_Moon(r,t)
        + sum[j=Earth,Sun] mu_j ((R_j(t)-r)/|R_j(t)-r|^3 - R_j(t)/|R_j(t)|^3)
        + a_command
a_command = F/m for finite burns; piecewise acceleration for descent
T = |F| for finite burns; m |a_command| for descent
dm/dt = -T / (Isp g0)
```

점질량의 `a_Moon=-mu_M r/|r|^3`은 기존 DE440 GM을 유지합니다. GRAIL의 `a_Moon`은 GL1800F GM의 중심항을 포함한 구면조화 퍼텐셜의 기울기입니다. 달 고정 PA 축에서 계산한 벡터를 실제 시각의 J2000 축으로 회전하며, 기존 중심항을 다시 더하지 않습니다. 전이 STM도 같은 퍼텐셜의 Hessian을 사용합니다. GRAIL의 1,738,000 m 계수 반지름은 1,737,400 m LOLA 고도 기준과 별개입니다.

지구·태양 상태는 적분 단계의 실제 시각에서 보간합니다. 선택한 달 중력과 지구·태양 중력은 NRHO 기준 상태 전파, 전이, 주차, DOI coast, 동력 하강 및 재검증에 동일하게 적용됩니다. LLO 진입 후 2체 모델로 바꾸지 않습니다. 100 km 원궤도 조건은 선택한 모델 GM을 사용한 진입 순간의 달 중심 osculating 조건이며 섭동을 받는 이후 경로가 정확한 원으로 유지된다는 뜻은 아닙니다.

`dynamics.ts`는 Dormand–Prince 5(4) 적응형 적분과 6상태 천이행렬을 구현합니다. 기본 상대 허용오차는 `2e-11`, 위치/속도 절대 허용오차는 `1e-4 m` / `1e-7 m/s`입니다. 후보 확정 때 더 엄격한 값으로 다시 적분합니다. 양·음의 전파 시간을 지원하며 지원 범위·계산 예산·비정상 상태·충돌 경계를 검사합니다. 시간에 따른 외력이 있으므로 Jacobi 보존이나 정확한 주기 폐합을 검증 기준으로 쓰지 않습니다.

## 전이와 동력 하강

1. 선택한 접지 UTC의 달 자세로 지형 목표와 표면 상대 접지 속도를 구성합니다. 시간·방향 미지정 시 최대 48개 후보(440/560/700/880초, 네 방향, 세 위상 초기값)를 전방 적분합니다. 기본 예제는 880초·180°를 지정하며 종말 제약 선별 후 전이를 계산합니다.
2. 각 하강 후보는 LLO의 평면·위상과 도착 시각을 정의합니다. 전이는 이 정확한 100 km 상태를 목표로 합니다. 임의의 기존 우주선 상태에서 시작하는 계획기는 아닙니다.
3. 각 착륙 후보의 전이·착륙 전체 비용을 비교합니다. 사용자가 지정한 범위 안의 최대 9개 시간(기본 예제는 3일 고정)과 short/long 초기 추정 중 넓은 범위의 3개 시각을 여러 접근 방향에 먼저 탐색하고 남은 격자를 평가합니다. 출발 시각은 `LLO 도착 시각 - 전이 시간`입니다. 그 시각의 출발 상태는 정적 NASA NRHO 표에서 직접 조회합니다.
4. Lambert 해는 초기 속도 추정에만 사용합니다. 실제 날짜 기반 중력과 상태 천이행렬로 Newton shooting을 수행하고 더 엄격한 적분으로 검증한 경로만 후보로 채택합니다. 기본 진입 위치 허용치는 0.05 m이며 ΔV, 궤도면, 이심률, 달·지구 충돌과 적분 정밀화 차이도 검사합니다.
5. 이탈·진입·DOI는 최대 추력·고정 관성 방향의 유한 연소입니다. 실제 힘과 질량유량을 적분하며 이탈·진입 벡터를 재표적화해 연소 종료 후 위치·속도 6성분을 LLO에 맞춥니다. DOI 크기는 vis-viva 초기 설계이며 실제 연소 종료 상태에서 PDI까지 전파합니다. 순간 상태 변경은 없습니다.
6. 실제 진입 상태에서 주차·DOI·하강을 다시 전파합니다. 위치를 목표 상태로 바꾸지 않습니다. 동력 하강은 조기 감속을 위한 5차 초기 추정을 사용한 96개 구간의 관성 가속도 명령을 shooting으로 보정하며 RK4로 위치·속도·질량을 적분합니다. 각 구간에서 추력은 질량에 따라 변합니다.
7. 모든 구간 경계의 추력, 연료, 표면 접촉, 지형, 위치·속도, 데이터 범위와 연속성을 검사합니다. 하강 제어는 0.25 s 이하 적분 후 0.125 s로 재검사하며, 무추력 착륙 구간도 별도의 적응형 적분으로 비교합니다.

질량 기준 `llo`는 입력 질량을 LLO 진입 후로 해석해 필요한 NRHO 시작 질량을 역산합니다. `nrho`는 입력 질량에서 전이 추진제를 차감하고 하강을 재계산합니다. 탱크 용량이나 시작 총질량 상한을 별도로 모델링하지 않습니다.

## 출력·검증·실패

`result.nrho.mode`와 `reference.mode`는 `EPHEMERIS`입니다. `trajectory`, 기동 이벤트와 제어 시작 시각은 전체 임무 시작부터의 경과 초를 사용합니다. 내부 전이 진단의 시간은 정적 ET epoch 기준이므로 [COORDINATE_FRAMES.md](../COORDINATE_FRAMES.md)의 시간 원점을 확인해야 합니다.

화면의 참조 미리보기와 출발 전 3시간 coast도 출발 상태에서 수치 적분한 표본입니다. 원본 SPK의 유지 기동이 반영된 경로를 그리는 것이 아니며, 미리보기 종료는 환경 데이터 끝에서 자릅니다. 참조 미리보기의 최대·최소 고도는 계산 시간창의 극값이며 주기궤도의 근월점·원월점이라는 보장은 없습니다. 지구 위치와 햇빛 방향은 재생 시각을 따르고 고정 L1/L2 표시는 제공하지 않습니다.

최신 날짜 확장과 대표·경계 날짜 결과는 [EPHEMERIS_EXPANSION.md](EPHEMERIS_EXPANSION.md)를 따릅니다. 이전 점질량 기준 보고서는 당시 모델의 전체 15개 검사를 통과한 이력입니다. GRAIL의 검사와 실제 실행 결과는 [GRAVITY_VALIDATION.md](GRAVITY_VALIDATION.md)에 별도로 기록합니다. 수렴 실패, 제약 위반, 기간 초과, 손상 데이터 및 중력 수치 오류는 성공 경로로 대체하지 않습니다. UI는 원인에 맞는 조정 방법을 보여 줍니다. 계산 시간·횟수 한도 또는 후보 집합 내 실패는 물리적 불가능의 증명이 아니며, 낮은 GRAIL 차수 추천은 속도와 생략 성분 사이의 절충입니다.

작은 위치 잔차는 구현한 결정론적 모델의 수치 일치도입니다. 실제 중력장 모델·항법·엔진·DEM 오차를 포함한 착륙 정확도가 아닙니다. GRAIL 선택 시에도 90차 초과 성분, 시간가변 고체 조석과 원본에서 제외한 영구 조석을 포함하지 않습니다. 다른 행성, 태양 복사압, 궤도 유지, 자세·짐벌·식 및 통신 제약도 포함하지 않습니다. Mode B 유한 연소는 최대 추력·고정 관성 방향에 한정됩니다. 모든 수치 결과는 [VALIDATION.md](../VALIDATION.md), [GRAVITY_VALIDATION.md](GRAVITY_VALIDATION.md)와 원시 보고서를 함께 확인합니다.

결과는 실제 사용한 모델·차수·GM·프레임을 함께 기록합니다. GRAIL의 동일 제어 진단은 성공한 임무의 실제 PDI 상태부터 같은 가속도 명령을 같은 GL1800F GM의 0차 모델로 재전파한 동일 시각 종단 차이입니다. 지형이나 새로운 접지 시각을 검사한 두 번째 임무가 아닙니다. 별도의 세션 비교 표는 중력 설정 외의 입력이 같은 검증 완료 임무를 각각 재최적화한 기록입니다. 두 비교의 목적과 범위를 혼동하지 않아야 합니다.

## 재현

프로젝트 루트에서 일반 실행 및 검증:

```powershell
npm install
npm run dev
# 별도 터미널에서 개발 검증
npm test
node scripts/run-finite-validation.mjs --degree=30 --budget=60
npm run build
```

Mode B를 선택하고 날짜 `2026-11-16T00:00:00Z`와 중력 모델·차수를 명시해 실행합니다. 위 명령은 현재 유한 연소·GRAIL 30차 모델을 검증합니다. 기존 점질량은 `--degree=point`를 사용합니다. GRAIL 재현 명령과 해당 보고서는 [GRAVITY_VALIDATION.md](GRAVITY_VALIDATION.md)를 따릅니다. 개발용 Node 검증 스크립트는 Worker와 같은 TypeScript 소스를 번들링해 로컬 정적 파일과 함께 실행하며, 사이트의 백엔드가 아닙니다. 위 명령은 `.cache/finite-mission-30-default.json`과 `docs/finite-mission-30-default.json`을 생성합니다. 프론트엔드는 이 저장된 경로를 로드하지 않습니다.

선택적 독립 검증은 원본 커널과 `numpy`, `scipy`, `spiceypy`가 준비된 개발 환경에서 실행합니다. 위 전체 결과 파일을 먼저 생성해야 합니다.

```powershell
py scripts/independent_verify_ephemeris.py --input .cache/finite-mission-30-default.json --output docs/finite-independent-validation-30.json
```

이 검증은 원본 SPICE 상태·자세와 독립 SciPy DOP853을 사용해 NASA 초기상태부터 추력 명령까지 연속으로 전파합니다. TypeScript 중간 상태로 재설정하지 않습니다. 종말 정책이 있는 출력은 원본 LOLA로 동력 하강도 검사합니다. 전 비행 구간 지형·미해상 장애물의 인증은 포함하지 않습니다.

지원 기간을 바꿀 개발자는 `py scripts/prepare_ephemeris.py --help`와 [데이터 문서](EPHEMERIS_DATA.md)를 확인하십시오. 자료를 재생성하면 검증·SHA 고정값·테스트·정적 빌드도 함께 갱신해야 합니다. 일반 사용자는 이 과정이나 Python 없이 실행할 수 있습니다.
